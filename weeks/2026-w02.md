### LFS101 - Chapter 2 - Core Concepts
- Kernel: the core of the operating system. It sits between the hardware and the programs, deciding which process gets CPU time, how memory is shared, how files are read from disk, and how data goes through the network.
- Distribution: the kernel plus the tools, package manager (apt, dnf) and default settings needed to actually use the system. Ubuntu, Debian, Fedora and Red Hat are distributions built on the Linux kernel.
- Kernel vs Distribution (also called distro): the kernel is the engine and the distribution is the whole car. The same engine can be used in different car models, just as different distributions can share the same kernel.
- One of Linux’s strengths is that it treats many system components as if they were files. Devices, processes, and even network connections are represented as file-like objects, which means users and applications can interact with them using the same commands and tools used for ordinary files.
- In Linux, all files are organized within a single unified directory tree that begins at the root directory "/"
- Firmware initializes hardware and loads the boot loader; the boot loader loads the kernel; the kernel starts systemd.
- Boot loader is a small program that sits at a known location at the disk and its sole purpose is to find and load the kernel. On Linux, the boot loader is almost always GRUB (GRand Unified Bootloader).
- The firmware is the first thing to start, and it's built into the hardware. It initializes just enough hardware (memory controller, storage bus), performs minimal hardware checks, and then looks for the boot loader. The usual firmware is called UEFI, while older machines used BIOS.
- The boot loader finds and loads the kernel (Linux, in our example) and then handles control to the kernel. The reason for the existence of the boot loader is that the kernel is too complex for the firmware to start, so it's a previous step in order to assure everything is in place for the kernel to handle control of the system.
- System capabilities: Linux is fully multitasking (many programs run "at once" via fast switching), multiuser (multiple people can be logged in simultaneously, each with their own processes), and has built-in networking. Together these are what let daemons exist.
- Daemon: a background program with no window, not tied to a user session, that waits to do its job whenever needed. `systemd`, `sshd`, and `journald` are all daemons.
- Naming convention: most daemons end in `d` (sshd, systemd, journald, cupsd, smbd), a useful hint when scanning a process list.

### LFS101 - Chapter 3 - Core Concepts
- Characteristics of some of the Linux Distributions:
  - The Red Hat Family: These distributions are widely used in enterprise environments and are common in large production systems. Examples include Fedora, Red Hat Enterprise Linux (RHEL), Rocky Linux, AlmaLinux, and CentOS.
  - The Debian Family: This family includes Debian, Ubuntu, and Linux Mint. Many new Linux users find Ubuntu or Linux Mint especially approachable and easy to install.
  - The Suse Family: This group includes SUSE Linux Enterprise and openSUSE. These distributions are known for their strong system management tools and stability.
- Some common software cathegories: 
  - Desktop Environment: If you need a graphical interface, you can typically choose between environments such as GNOME or KDE Plasma, each offering a different look, feel, and workflow.
  - Productivity Applications: Office suites (LibreOffice), web browsers (Firefox), and media players are typically offered as optional bundles.
  - Development Tools: Text editors, compilers, and version control tools such as Git can be included during installation or added later.
  - Server Software: Components such as the Apache web server or MySQL database can be pre-selected if the system's role is known at install time.
- PXE (Preboot Execution Environment) is mostly used in companies that need to install the operating system on many machines (tens or hundreds) without walking to each one with a USB drive. Instead, everything is done from one central place.
  Breaking it down:
  - "Provisioned" means set up and made ready to use: install the OS, configure it, hand it over.
  - "Central location" means one server that holds the installation files and serves them to all the other machines
  - "Enterprise environments" means large organizations, like banks and data centers.
- General steps in an Installation Proccess
  a) Boot from the installation media: The machine starts the Linux installer instead of loading an existing operating system. At this point, you may be presented with options such as starting the installation directly, booting into a live environment to test the system, or running a memory test.
  b) Configuration questions: The installer walks through a series of setup questions (ex. language, timezone, network configuration, etc). If an automated installation file was provided, these questions are answered automatically, and this step is skipped entirely.
  c) Installation: The installer formats the partitions according to the chosen layout, copies the operating system files, installs any selected software packages, and configures the bootloader (the small program that starts Linux each time the machine powers on).
  d) Updates: Most installers offer the option to download and apply available updates during installation. If skipped, the system's built-in package manager can retrieve the same updates once the system is running.
  e) Reboot and first boot: The machine restarts into the newly installed system. Some distributions perform a small amount of additional first-boot configuration at this stage, such as accepting a license agreement or completing account setup.
- Introduction to the boot proccess:
    a) BIOS (or UEFI): it's the firmware. BIOS means Basic Input/Output System, which gives us a picture of its function. The BIOS performs a series of checks and initializations known as the Power-On Self-Test (POST). During POST, the BIOS initializes critical hardware components such as the screen, keyboard, and memory, ensuring that everything is functioning correctly before the operating system loads. The BIOS also finds and loads the bootloader, which then starts the operating system.
    b) Master Boot Record (MBR) or Unified Extensible Firmware Interface (UEFI): Once the Power-On Self Test (POST) is complete, control of the system passes from the BIOS to the boot loader (MBR, EFI or UEFI). The boot loader is a small program stored on one of the system’s storage devices. Most Linux boot loaders provide a menu or user interface that allows you to choose between multiple operating systems or different Linux kernel versions. When you select a Linux option, the boot loader’s main job is to load the kernel image and the initial RAM disk (`initrd` or `initramfs`) into memory.These components contain essential drivers and files that keep the system booting until the whole operating system is loaded.
    c) Boot Loader in action: for systems using BIOS/MBR firmware, the boot loader is stored in the first section of the hard disk, known as the Master Boot Record (MBR). During this stage, the boot loader: 1) Examines the partition table to locate a bootable partition; and 2) Loads the second-stage boot loader (such as GRUB) into RAM (Random Access Memory). For systems using the EFI/UEFI method, the process is more advanced. The UEFI firmware reads its Boot Manager data to determine which UEFI application should be launched and where it is located, specifically, which disk and partition contain the EFI System Partition (ESP). The firmware then launches the defined UEFI application (for example, GRUB), as specified in the boot entry. The second-stage boot loader is typically stored under the /boot directory. At this stage: 1) A splash screen appears, allowing you to choose which operating system (OS) and/or kernel version to boot; and 2) Once the OS and the kernel are selected, the boot loader loads the kernel into RAM and passes control to it.
    d) Initial RAM Disk: the kernel is always compressed when the boot proccess starts, so once its decompressed, it faces a technical limitation: the kernel needs to mount the root filesystem to access system tools, but the drivers required to talk to the storage hardware are often stored on that very filesystem. To solve this, the system uses the Initial RAM Disk (initramfs) as a temporary bridge. The initramfs is a small, compressed filesystem image that the boot loader pulls into memory alongside the kernel. The initramfs is a set of programs and binary functions that: mount proper root filesystem, provide kernel functionality, locates devices, locates drivers and load them, checks for errors in root filesystem. Without a properly built initramfs containing those essential drivers, the boot process would stall, unable to access the storage it needs to finish loading.
    e) Text-Mode Login: As the boot process nears completion, the init process launches several text-mode login prompts. These prompts allow you to enter your username and password to access a command shell. 
    f) The Linux Kernel: As soon as the kernel is active in RAM, it begins a comprehensive configuration process to "claim" the hardware. The initialization is driven by functions that systematically bring the hardware to life: memory management, processor setup, I/O (input/output) and Storage. The kernel does more than manage hardware; it also starts the user space, which is the environment where your programs run. It uses the drivers and files stored in the initramfs to create what is known as "early userspace". This early userspace is critical because it contains the logic required to find, check, and mount the primary root filesystem on your disk. Once that filesystem is verified and ready, the kernel transitions from this temporary environment to the permanent operating system. Finally, it loads the essential applications needed to finish the boot sequence.
    g) /sbin/init and Services: After completing hardware initialization and mounting the root filesystem, the Linux kernel launches the first user-space process: `/sbin/init`. This init process becomes the parent of all other user-space processes and starts the services and applications needed to bring the full operating system to a usable state.
- Common Linux Filesystem Types:
    a) Conventional Disk Filesystems: these are the "workhorses" for standard hard drives and SSDs. Common examples include ext4 (the most widely used), XFS (excellent for large files), and Btrfs.
    b) Flash Storage Filesystems: Optimized for raw flash memory (like those in embedded devices), such as ubifs or yaffs.
    c) Special Purpose Filesystems: These often exist only in memory to provide system information, such as procfs (found at /proc) or tmpfs (temporary volatile storage).
    d) Database Filesystems: These are a specialized type of filesystem that treats data not as a collection of simple files and folders, but as objects or rows within a database. While standard filesystems like ext4 or NTFS are optimized for storing blocks of data on a disk, a database filesystem is designed for high-speed searching, metadata richness, and data integrity.
- Partitions and filesystems: Disk → Partition → Filesystem → Mount point
    1. Disk (the hardware). The physical device. In your lab1, it is /dev/sda.
    2. Partition (a slice of the disk). You cut the disk into separate areas. Each area is managed on its own. The name shows this: /dev/sda1 = first partition of disk sda. In your df output, you have three: sda1 (the system), sda15 (UEFI boot) and sda16 (/boot).
    3. Filesystem (the organization inside a partition). A new partition is empty and unorganized ("raw"). Formatting it writes a filesystem onto it (ext4, XFS), which lets Linux create files, folders, names and permissions.
    4. Mount point (the door into the tree). A filesystem is only usable once attached to a directory. Example: if you mount /dev/sdb1 on /home, everything you save in /home is written to that partition.
- The Filesystem Hierarchy Standard (FHS): The FHS is a specification that establishes the names, locations, and intended purposes of directories across Linux (and other Unix-like) systems.

### LFS 101 - Chapter 7 - Core Concepts
- The pipe symbol (|), which takes the output of one command and feeds it as input into another. It's one of the more useful features of the shell, and it behaves identically regardless of distribution.
- Most commands entered at the shell prompt break down into three parts: (a) Command - The command is the specific program, utility, or script you are telling the terminal to execute; (b) Options - Options are switches, typically prefixed with a single dash (-) for short forms or a double dash (--) for long forms, that alter or expand how a command behaves (e.g. -p or --print); (c) Arguments - An argument specifies the target of a command, defining the exact file, path, or data the command should process.
- Basic Operations: Overview
  - Logging In and Out: An available text terminal will prompt for a username (with the string `login`:) and password. When typing your password, nothing is displayed on the terminal (not even a * to indicate that you typed in something), to prevent others from seeing your password. After you have logged into the system, you can perform basic operations. Once your session is started (either by logging into a text terminal or via a graphical terminal program), you can also connect and log into remote systems by using Secure SHell (SSH).
  - Rebooting and Shutting Down: 
    (a) `shutdown -h` (-h is short for halt) and it halts the system (powers off). The halt and poweroff commands are often aliases for this action. `Shutdown -h`needs a time to be complete, for example `shutdown -h now` or `shutdown -r now`. With no time given, `shutdown` waits 1 minute by default. `shutdown -r +5` reboots in 5 minutes, and logged-in users see a warning.
    (b) `shutdown -r`: Reboots the system. The reboot command is an alias for this. The timming concept of `shutdown -h`applies to this command.
- Accessing Directories:
  - Absolute Pathname: An absolute pathname begins with the root directory (/) and follows the tree, branch by branch, until it reaches the desired directory or file. Absolute paths always start with /.
  - Relative Pathname: A relative pathname starts from the present working directory. Relative paths never start with /.
  - Multiple slashes (/) between directories and files are allowed. However, all but one slash between elements in the pathname is ignored by the system. While  ////usr//bin is valid, it is seen as just /usr/bin by the system.
- Moving from one directory to another: (a) using the absolute pathname method `$ cd /usr/bin`; (b) using the relative pathname method: `$ cd ../../usr/bin`

### LFS101 - Chapter 7
- `cat`: displays a file's contents (or combines/concatenates multiple files together)
- `head`: displays the first few lines of a file
- `tail`: displays the last few lines of a file
- `man`: opens a command’s documentation page (man page)
- `sudo`: sudo ("switch user and do") allows a user to run commands with another user's privileges (typically root's) without logging in as that user directly. For Windows users, sudo is roughly equivalent to "Run as Administrator." On macOS, it's the same sudo command, since macOS shares Unix ancestry with Linux.
- `sudo -i`: sudo runs something as administrator, and -i asks for an interactive login shell as root. So instead of one command with privileges, you get a whole session with them. Everything you type from that point runs as root, with no permission checks. A mistyped rm there can wipe the system, and that's why snapshots exist.
- `sudo systemctl isolate multi-user.target` stops the graphical session and leaves text mode
- `sudo systemctl isolate graphical.target` brings the desktop back
- `ls`: lists the current directory
- `ls -la`: shows everything, including hidden files, with details (owner, permissions, size)
- `which`: searches only the directories in your PATH, the list of places the shell looks when you type a command. It answers: "which file would run if I typed this?" `which ls` prints /usr/bin/ls. It shows just the first match. `which -a python3` shows every match in PATH.
- `whereis`: It searches a fixed set of standard locations, not your PATH. It answers: "what files exist for this command?" and returns the binary, the man page and the source, if any. `whereis ls` prints something like ls: /usr/bin/ls /usr/share/man/man1/ls.1.gz
  - When to use each 
    Use `which` to debug "which version am I running?", for example when two versions of Python are installed and the wrong one runs. It respects your PATH, so it shows what the shell would actually pick.
    Use `whereis` to find where a program and its documentation live, even if the binary isn't in your PATH.
  - Limits to know
    `which` doesn't see shell built-ins or aliases. `which cd` finds nothing useful because cd is built into the shell. `type cd` covers those cases, and `type -a ls` shows aliases, built-ins and files together.
    `whereis` only knows its standard directories, so a program in a custom folder won't show up. 
- `echo`: the echo command prints a line of text or the value of a variable to the screen (in our example `echo $HOME`, the path stored in $HOME) and is used constantly in scripts and for inspecting environment variables.
- Navigating Around Directories
  - `pwd` means print working directory and its output is the folder you are working on.
  - `cd <directory>`: means change directory to <directory>. So if you are in the home directory and wants to go to the temporary files directory you'd type `cd /tmp` and that would lead you to the temporary files directory. If you just type `cd` it will lead you to your home directory (it also works with `cd $HOME`).
  - `pushd`: go to a directory and save the current one on the stack
  - `popd`: remove the top entry from the stack and go back to it
  - `dirs`: show the directory stack (`-v` for a numbered list)
  - `dirs -c`: clears the stack.
